# Design gap locations

Every finding from the design audit of `packages/gp-webapp` run on
2026-11-12, one row per finding, each tagged with the gap it was filed
under. `product-design-gaps.md` is the summary: it groups these rows into
gaps and components and ranks them in its migration order. Read this file
when you fix a gap and need every place it shows up.

How it was made: a mechanical scan of the app for known patterns
(restyles, raw elements, palette colors, off-scale type, disabled
buttons, hand-built states), then a review of each zone against
`product-design.md`, `product-copy.md` and `design-memory/learned.md`,
then a verification pass that opened every cited line, dropped findings
that didn't hold and corrected lines, severities and gap ids. Section
numbers (§) are `product-design.md`; "learned #N" is
`design-memory/learned.md`.

Paths are relative to `packages/gp-webapp/app/` unless they start with
`../`. Line numbers are as of the audit date and drift as code changes.
A row lists one representative line; the gap entry and the "+N" count
give the other places with the same problem. "Visual pass" at the end lists
what screenshots of the running product showed, by product, with its own
counts. Keep this file current: when you fix a row, add `fixed #<PR>` to its
gap cell in the same PR, and set the gap entry's status when its last row is
fixed; when you find a new place, add a row under its gap. Fixed rows are
removed in the sprint cleanup, not one by one, so parallel PRs don't
conflict.
