# Email outreach

Candidates (Win) and elected officials (Serve) email their opted-in contacts through Amazon SES. Until the shared contact lists land, a small test upload writes recipients straight onto a send. Design: TDD "2026-10-26 | Email outreach channel v1" (ClickUp doc `2ky4jq2q-20493`, page `2ky4jq2q-157273`); step lists, infrastructure and testing are on its Implementation Notes page (`2ky4jq2q-157293`). Payment goes through `src/paymentHolds/` (see its AGENTS.md).

## Invariants: do not break these

- **One sender at a time.** Only the holder of the `email_sweep_lease` row sends; the lease is the global SES rate limit. Don't swap it for a `CronLockService` minute claim, whose 30-second stale window is shorter than a sweep tick.
- **Recipients are claimed with `FOR UPDATE SKIP LOCKED`** (raw SQL, since Prisma `updateMany` has no limit). Duplicate-send exposure rests on this claim.
- **A send starts only when its hold is `held`,** re-checked against Stripe through `PaymentHoldsService.getHold`. Every capture goes through `settle`; email implements the settlement adapter and never captures itself.
- **The warming cap (`recipientCap`) is frozen at confirm** and never raised.
- **The shared SQS queue is never reconfigured** (encryption, deduplication or new producers). Replies arrive by SNS at `POST /v1/email/webhooks/sns`, which enqueues them like any other producer. Other systems send to this queue too.
- **The SNS webhook is public and trusts nothing it hasn't verified:** signature, certificate host, then topic (`EMAIL_INBOUND_TOPIC_ARN`). It does no processing; it answers 200 only after the enqueue succeeds.
- **Replies are read only from this environment's bucket:** `process` rejects any `bucketName` other than `EMAIL_INBOUND_BUCKET` (`goodparty-email-inbound-<env>`, set by Pulumi).
- **Never forward a message from our own domain, or one carrying `X-GoodParty-Forwarded`.** That is the forwarding loop guard.
- **Per-email SES events never go through the queue.** Bounce, complaint and send counts come from SES's CloudWatch metrics, tagged per send. If delivery, open or click data is ever needed, add a configuration-set event destination to Firehose and S3; one message per email would back up every other job on the queue.
- **Each organization sends as its own SES tenant** (`OutreachEmailSender.sesTenantName`), so SES pauses one organization instead of the account. Every send passes `TenantName`.
- **Bounces and complaints are suppressed by SES's account suppression list,** not our table. `OutreachEmailSuppression` holds only unsubscribes.
- **Previews and tests never call real SES.** `VENDOR_CRONS_ENABLED` is true wherever vendors are mocked, so SES must be a mocked vendor. Dev sends only to allowlisted addresses and the SES mailbox simulator.
- **Suppressions are scoped by `organizationSlug`.** Office sends also honor the campaign's organization, through `ElectedOffice.campaignId`. Unsubscribe tokens carry the email and organization, never only a row id.
- **Theme keys are never edited in place.** Sends store only the key, so a changed theme gets a new key.
- **Copy is mode-keyed** (`docs/product-vocabulary.md`): voters and a campaign on Win, constituents and an office on Serve.

## Send lifecycle

`draft` → confirm → `pending_payment` (cap frozen) → `pending` once the hold is `held` or `scheduled`. A decline stays `pending_payment`; the card route (`paymentHolds`) changes the card, and confirming again moves the send to `pending` (the due sweep also starts it if the hold is `held` by then). The due sweep starts a send whose hold is `held` (`in_progress`, enqueue prepare), and fails one whose hold is anything else at send time (releasing it first if it can), so it is never sent; prepare re-checks the hold too. Prepare sets `preparedAt`; the sweep then sends. A send is finished when nothing is queued or sending, or when `stoppingAt` is set (a cancel, or the hold module's expiry guard). The settle sweep calls `settle`, then, once SES's numbers have had 5 minutes, deletes the template, advances warming if the send was clean, and sets `completed` (or `canceled` if recipients were left).

- **Pauses:** `bounce_rate`, `complaint_rate` and `manual` (a rendering failure or a batch SES rejected) from the sweep; `ses_tenant` when SES says the tenant is disabled (`MessageRejected` naming the tenant ARN); `ses_account` and `daily_quota` for the whole account, which the sweep clears itself once SES allows sending again.
- **A send that sent nothing is charged nothing** (the hold is voided). Otherwise the larger of 50 cents and a cent per email SES accepted.
- **Unsubscribes are honored mid-send.** Prepare drops them once, and every sweep tick deletes the queued recipients of each running send who have unsubscribed since, so a long or paused send never reaches them.
- **SES calls make one attempt** (`maxAttempts: 1`): the SDK's own retry of a timed-out `SendBulkEmail` could resend a batch SES already accepted. A failed batch goes back to `queued` for the next tick, which is the one remaining duplicate exposure.
- **Dev sends only to `goodparty.org` and the SES mailbox simulator** (`isBlockedByDevAllowlist`); other recipients are marked `failed`. The test send refuses other login addresses there.
- **SES names carry the environment** (`<env>-<organizationSlug>` tenants, `<env>-email-<id>` templates, `outreach-<env>` set). A live deploy with no `OTEL_SERVICE_ENVIRONMENT` refuses to send.

## Gotchas

- Email drafts are `Outreach` rows with `status: draft`; the generic `POST /outreach` rejects `outreachType: email` (`createOutreachSchema`), so this module is the only way to make one.
- `POST /` is a full replace: omitted optional fields are cleared.
- The test upload is the only recipient source until the shared lists land. It writes consent onto the send, and it is refused once the send leaves `draft` (the transaction claims the `Outreach` row, so it serializes with a confirm).

- **Deployed dev sends through the SES mock,** and `VENDOR_MODE=live` there turns the crons off, so nothing deployed ever exercises real SES before prod. `scripts/email-dev-e2e.ts` runs the real prepare, sweep, auto-pause, finish and inbound services from a laptop against real dev SES and the mailbox simulator. The release-train spec `gp-webapp/e2e-tests/tests/app/dashboard/outreach/email-send.spec.ts` covers upload, compose, pay and send against the mock, driving the sweeps through the `email.*` test-fixture jobs.
- `src/scheduled-messaging/` and `EmailService` (Mailgun) are transactional email. Don't build outreach on them.
- **SES won't delete a template a tenant still holds.** Finishing removes the tenant association first.
- Merge values go into SES's Handlebars template unescaped by us: Handlebars escapes the html part, and the sweep strips `<>{}` from names so the text part stays readable.
- Which address bounced isn't tracked per message. SES's `ListSuppressedDestinations` keeps every hard bounce and complaint with its date, so they can be matched back to recipient rows later.
