| `components/OutreachComposeDeepLink.tsx` | Consumes `?compose=text\|robocall\|phoneBanking\|social` (+ `?message=`, `?due=`, `?listId=`, `?recommended=`, `?source=`, `?handoff=`) — runs the channel gate (text: the 10DLC gate; robocall: the Pro modal; phone banking: the tile's `/dashboard/pro-upgrade` redirect; social: none), hands the hub a `ComposeRequest`, then strips the params (consume-once via `router.replace`). A `?compose=text` arrival while gp-api reports texting `closed` opens `SmsCutoffNoticeDialog` instead, on both sides of the flag (see "SMS compliance cutoff"). Runs the same flag switch the tiles do: behind `outreach-pro-gating-v2` the text, robocall and phone-banking arrivals skip those three gates entirely and hand the request over, so a free candidate's `?compose=text` opens the flow instead of the Pro wizard. A bare `?listId=` or `?recommended=` (read server-side) is stripped the same way. Takes an optional `resumesDraft(type)` predicate from the hub (which owns the saved-draft lookup) so `ClickCreate` can carry `resumed: true` instead of counting a resume as a create. On `?compose=social`, `?handoff=<nonce>` is the Campaign Manager's `compose_handoff` (ENG-11218): loads+deletes the `cos-handoff-<nonce>` sessionStorage entry the chat wrote, `safeParse`s it against `ComposeHandoffPayloadSchema`, and keeps only a `win_social` payload (a `serve_social` one under a nonce here is ignored, same as a missing/expired/malformed one) — resolves to `ComposeRequest.socialPrefill`, never an error, so an arrival with nothing to show still opens a blank flow |
