| `crm/recommended/`                      | The "Recommended voter lists" section above the saved lists (Win only): the GLOBAL recommended universes from `GET /v1/campaigns/mine/recommended-lists` with no channel (`useRecommendedLists.ts`), one `RecommendedVoterListCard` per recommendation (sparkle eyebrow, title, summary, count, Details, Send outreach), and `RecommendedListDetailSheet` — every `CrmSheet` section a saved list's detail has, fed by `POST /v1/contacts/list-detail` with the recommendation's filter (`recommendedListDetail.query.ts`, shared with the channel picker): the filter summary, the five demographics tiles with Last outreach/Last method reading "—", reachability, an outreach-history section reading "No outreach yet.", and a footer Download that streams `GET /v1/campaigns/mine/recommended-lists/:variant/download` through `useContactsDownload`'s `downloadFromHref` (the saved-list `download()` now builds its href and delegates to the same routine); no kebab, since there is no saved row to edit, copy or delete. | `citizens-panel/`                       | Serve's civic panel, behind `serve-citizen-panels`. `components/CitizensPanelSection.tsx` sits on the Serve Contacts page under the district stat card (the panel page's headline count, "{members} of {goal} residents have joined" from `joinedOfGoal`, then the seats, `CivicPanelSeats` from the summary's `composition`, then members, reached in the last 30 days, ready to ask, all from `GET /v1/contacts/civic-panel`; the empty state says nobody has joined yet). `page.tsx` is `/dashboard/contacts/citizens-panel` (`serveAccess`, server-side flag, `notFound()` off), the panel's page (below). "See members" there links to the built-in list below (`CITIZENS_PANEL_LIST_PATH`). The built-in "Civic panel" row (`crm/lists/CitizensPanelListCard.tsx`) sits under All constituents once the office has a member, with the live count from the same `civicPanelSummaryQueryOptions` key the section reads and its "Last outreach <date>" / "No outreach yet" line from the same summary's `lastOutreachAt` (the newest row of the sheet's outreach history, so the row never spends a list-detail request); Details is `selectList(CIVIC_PANEL_SEGMENT)`, so `/dashboard/contacts/lists/civicPanel` opens `ListDetailSheet`'s panel mode, which renders a saved list's body: the "Constituent list details" heading, the panel's filter sentence, the members by name (`crm/lists/CivicPanelMembers.tsx`, each opening the record in `PersonOverlay`, from the same `useListPeople` read as the map, so one request and no export of its own), the members' map (`ListMapSection builtInListId`, `GET /v1/contacts?segment=civicPanel`, read-only: no Draw shapes, since a boundary is written to a saved row), demographics with Last outreach/method, reachability and the outreach history from `GET /v1/contacts/list-detail?segment=civicPanel` (the history is every send that reached a current member), and Download by the same segment. Like All constituents its header is only the title (no rename, kebab or delete). Never a saved list, so never duplicated; panel lists officials saved themselves stay ordinary lists. The lists gp-api saves for a managed panel wave's invite (saved with `civicPanelInvite: true`) are left out of `ListsIndex`: the outreach that used them keeps them, and the flows still find them in `GET filters`. Duplicating one drops the marker, since the copy is the official's. Flag off or Win, the path is an unknown list. Copy in `citizensPanelCopy.ts` (`SERVE_CITIZENS_PANEL_COPY`). The static route wins over `[[...attr]]` |
| `crm/shared/channelPicker/`             | The prototype's "Choose a channel" sheet every Send outreach on this page opens — list cards, the universe row, both detail sheets (which close themselves first; two full-height sheets never stack) and the recommended cards. One instance, mounted by `ChannelPickerProvider` in `CrmContactsPage` and opened through `useOpenChannelPicker(target)`, where the target is a saved list, the universe, or a recommendation. Header: the list name and its people count; one row per channel (SMS, Robocall, Phone banking, Door knocking, Social media — labels/icons from `outreach/v2/channelMeta.tsx`) with how many of the list it reaches (the list-detail reachability leaf, fetched under the same query keys the detail sheets use, `POST list-detail` for an unsaved recommendation) and the cost at the flows' own per-contact price (`OUTREACH_OPTIONS`, tenth-cent integer math so it matches checkout) or "Free"; rows sort by reach, social last. No "Most effective" badge on purpose (channel recommendations are Jared's team's call, not an automated pick). Each row is a link built by `channelPickerHref.util.ts`: the hub with `?compose=<flow>&source=voter_data` plus `?listId=`/`?recommended=` (door knocking navigates straight to `/dashboard/door-knocking?create=1…`), because the hub owns the one mount of every flow                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
