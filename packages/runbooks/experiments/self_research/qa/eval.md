# self_research — eval rubric

You are grading a `self_research` artifact, generated by an LLM for a political candidate. It is a list of **vulnerabilities in the candidate's own public record**, each with a drafted response. Grade it against the criteria here. That is the whole job: read the artifact once, apply each check, record a verdict.

## Keep this evaluation editorial, not investigative

Score the artifact's OWN embedded content as written, in a single read. The evidence universe is closed: you may compare a claim ONLY against what the artifact provides — each finding's `source_extract`, `source_url`, `claim`, and `drafted_response`. Do NOT web-search, do NOT fetch the `source_url`, and do NOT fact-check against the outside world. A `source_url` tells you a claim is attributed to that page; it is not an invitation to fetch it. Per-claim grounding (does the extract appear on the page) is the agent's own `verify_quote` gate and the deterministic `qa/main.py` stage — not your job. Your job is editorial quality and tone.

## Inputs

- **The artifact** is a JSON `self_research` output under `/workspace` (read-only evidence — find it with `Bash`, e.g. `ls /workspace/output`). You MUST NOT modify `/workspace` or the artifact.
- You have ONLY `Bash`, and only to read the artifact. You cannot write to the workspace, fan out subagents, web-search, or use MCP.

## Eligibility gate — checked FIRST

Read `findings`.

- If `findings` is an empty array → there is nothing to grade. Emit ONLY the `gate_eligibility` fragment with `passed: false` and a short `detail` ("no findings — nothing to grade"), and stop. An empty list is a valid honest result, not a quality failure.
- Otherwise → the gate passes. Emit `gate_eligibility` with `passed: true` and grade the checks below.

## The checks

Score each as Pass or Fail. On a Pass write no `detail`. On a Fail write a single-line note, hard cap 300 characters: `<defect> | <locator: finding index / category> | <evidence: verbatim snippet>`.

### 1. Scope discipline → `scope_discipline`

Every finding must be about the candidate's OWN public conduct, and must not cross the "never do" allowlist.

**Fail if:** any finding touches a relative, the candidate's health, or private life; rests on rumor/innuendo/anonymous claims; or attributes another person's conduct to the candidate.

**Pass if:** every finding is a specific, public, on-the-record vulnerability in the candidate's own conduct.

### 2. Specificity → `specificity`

Each `claim` must name a concrete instance (a vote, a statement, a donation, a date, a dollar figure, a place), not a vague category.

**Fail if:** a claim is generic ("the candidate has a weak record", "questions about funding") with no named instance.

**Pass if:** every claim names the specific thing an opponent would attack.

### 3. Response quality → `response_quality`

Each `drafted_response` must be a usable, honest reply grounded in the same facts — not spin, not a non-answer, not an attack on the source.

**Fail if:** a response dodges, denies a sourced fact, or is empty/boilerplate.

**Pass if:** every response addresses the vulnerability honestly and would be safe for the candidate to say.

### 4. Tone → `tone`

Plain, direct U.S. English. Neutral, professional framing. No em dashes, no inflammatory or partisan editorializing in the `claim` or `drafted_response`.

**Fail if:** any field is sensational, partisan-loaded, or stylistically off (em dashes, slogans).

**Pass if:** the artifact reads as a sober, professional self-audit throughout.

## Output — write a contract-C fragment array to the result file

The harness injects a **result-file path**. Write your verdict there as a single JSON array of fragments — nothing else, no prose, no markdown fences.

Each fragment: `{"name": "<check-id>", "type": "agent", "passed": <bool>, "detail": "<fail note — only on a fail>"}`. These are Pass/Fail (omit `score`/`min_score`). `passed: true` carries NO `detail`. The `gate_eligibility` fragment carries a short `detail` only when it disqualifies.

- **Gate disqualifies** (empty `findings`) → emit ONLY `gate_eligibility` (`passed: false`). Stop.
- **Gate passes** → emit `gate_eligibility` (`passed: true`), then `scope_discipline`, `specificity`, `response_quality`, `tone`.

Constraints: keep every `detail` to one concise line (≤ 300 chars). Never echo secrets or token-shaped strings. The result file must contain EXACTLY the JSON array.
